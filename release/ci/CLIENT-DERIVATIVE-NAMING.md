# Client derivative names

These are Polaris-maintained derivatives of the fixed SagerNet clients, not official upstream SagerNet releases. The user-selected product display name is `sing-box-polaris`. Original authors, copyright statements and license texts remain intact. This naming change does not assert permission for any component whose grant remains unclear; existing source-material observations remain applicable.

The existing source-owned overlay replay changes Android's five locale labels, notification/session display text; desktop window/tray/menu labels and Windows installer product display; and Apple bundle display labels, visible brand strings and package/volume titles. SFA/SFW/SFL/SFI/SFM/SFT schemes and packaging formats remain unchanged. Application/bundle IDs, signing identity and entitlements, URL schemes, daemon/service/socket names and persistent data paths remain unchanged. Linux's internal product/install name stays `sing-box` so `/opt/sing-box` and desktop executable integration remain valid; its menu, main UI and tray display `sing-box-polaris`. Windows keeps the `sing-box` executable name.

The desktop's pinned dashboard is not silently modified. An exact-path, SHA256- and anchor-checked Vite pre-transform changes the desktop sidebar/local server and connection-page label. The transform itself is included in the desktop overlay diff and immutable source archive; the original dashboard submodule is preserved.

The existing publisher `default_name` boundary maps validated upstream candidate names to public derivative names. Examples: `SFA-V-other-arm64.apk` → `sing-box-polaris-SFA-V-other-arm64.apk`; `SFW-V-x64.exe` → `sing-box-polaris-SFW-V-x64.exe`; `SFL-V-amd64.deb` → `sing-box-polaris-SFL-V-amd64.deb`; `SFM-V-Universal.pkg` → `sing-box-polaris-SFM-V-Universal.pkg`; `unsigned-V-ios.xcarchive.tar` → `sing-box-polaris-unsigned-V-ios.xcarchive.tar`; `sing-box-V-ios-app-store.ipa` → `sing-box-polaris-V-ios-app-store.ipa`. Already branded names are idempotent. Exact candidate paths remain in the aggregate receipt; upstream scope, matrices, payload extensions and counts are not changed. Existing publisher collision checks remain authoritative. Consumers that matched public client asset names must adopt these prefixes or use receipt mappings; core/native-index identities are unchanged.

Android material reference distinguishes the historical diagnostic's original overlay identity from the newly reviewed display-only overlay. It preserves the raw historical run and graph hashes. No new Gradle measurement is claimed. Formal producers still submit fresh actual graphs and pass exact external-artifact identity and byte checks. This patch requires new source and product producers; old outputs and tags are not relabeled. Material status remains current-scope-review-required until separately reviewed; no publication approval is inferred from naming.

## Native and other public assets

All remaining public `sing-box-` or `sing-box_` product prefixes become `sing-box-polaris-` or `sing-box-polaris_`, including 44 native archives, upstream distro archives and OCI/container downloads. Already branded distro packages are unchanged. AAR and Libbox API-library basenames retain their existing versioned identity. Internal executable names, archive roots, member paths, package IDs and container registry names are unchanged.

The existing v1 native index now requires `platforms[].archive.releaseName` in newly produced indexes. It is exactly `sing-box-polaris-` plus the suffix after `sing-box-` in the independently validated candidate `archive.name`. `archive.name`, row ID/root and bytes/SHA256/members retain their existing semantics. Publisher validates the mapping and publishes those same bytes under `releaseName`. The Polaris consumer must use this field for its Release asset lookup and validate the exact mapping; old indexes without the field may retain the old-name lookup, but null, wrong names, paths, URLs or mismatched versions/platforms must fail. Consumer compatibility is coordinated separately and must be delivered before using new public assets. No alternate download host or arbitrary redirect is introduced.

The `build.yml` (`all`) and `linux.yml` (`linux`) producers supply distinct DEB/RPM payloads; 22 current pairs would collide after a simple prefix replacement. All `build.yml` legacy `sing-box_...deb/rpm` public names therefore include `-build` immediately before the extension (for example `sing-box-polaris_V_linux_amd64-build.deb`). The existing `linux.yml` name `sing-box-polaris_V_linux_amd64.deb` remains unchanged. Neither payload is dropped, merged, or claimed byte-equivalent. All other package extensions retain the prefix-only mapping.
