# Polaris fork maintenance and scope

The source-owned production plan pins upstream `v1.15.0-alpha.12` / `25b0d5ea3e466d246c708ac0f20d0448110e566c`. `polaris-main` carries the full reviewed runtime and producer history; an independent batch branch accumulates all current implementation. The upstream `testing` branch is a development mirror, never a substitute for a released production baseline. Current product tags have the same spelling as upstream release tags; self-check fetches the upstream baseline into `refs/polaris/upstream-baseline` and compares the exact peeled commit, without replacing a product tag.

## Original functionality and later additions

`polaris-fork-maintenance.json` maps the fourteen original product patches plus dial-side DNS rules to their origin commits, implementation/test paths and the current reviewed runtime reference. The actual alpha.11→alpha.12 upstream endpoint delta changes only `build.yml` and the changelog, leaving these runtime paths unchanged; the catalog records retain-at-this-baseline decisions and their bounded evidence. It verifies the actual 64 Git blobs and SHA256s; the catalog does not infer behavioral acceptance or upstream equivalence from file presence. The later Windows DNS local sing-tun replacement remains separately pinned by `dependency-sources/sing-tun-replacement.json`, the source collector and production BuildInfo/replacement checks.

The original capabilities are API listener close ownership, Naive inbound HTTP/3 keep-alive, clash-mode synchronization/default mode, Windows system DNS refresh, local search domains, sticky box close result, construction-scope cleanup, Tailscale state-store retirement, transient command server, Android interface binding, per-instance default-interface monitor, mobile DNS cancellation/sealing, strict command server and structured config validation. Dial-side DNS rules are opt-in, retaining bootstrap/IPv6/cancellation/cache and existing default behavior. Deployment of a server using the keep-alive patch is owned by the separate server project.

All three CLI presets and the Android/Apple build helper retain `with_gvisor`; this compiles the capability without changing the stack default. `DEFAULT_BUILD_TAGS_OTHERS` excludes Naive/Cronet and retains its existing wider architecture consumers. Six desktop cores use prebuilt Cronet (Linux/Windows sibling .so/.dll, macOS static .a); two musl cores use fixed static .a. Android JNI and Apple framework helpers already link matching prebuilt libraries into their native artifacts. No available Cronet binary is rebuilt from Chromium merely for acquisition. The current production publisher ships only six desktop archives and four OpenWrt packages; mobile AAR/XCFramework production receipts and App final carriers belong to their agreed later owner batches. Preserving a helper or a successful package compilation is not mobile/device acceptance.

## Read-only maintenance audit

After all code logic is complete, the single production workflow plan performs:

```
python3 -B scripts/polaris_fork_maintenance.py --source <exact-checked-out-SHA>
```

The audit requires clean source, exact production/catalog baseline and runtime-reference ancestry, and all catalog bytes. It writes JSON to stdout only, never fetching/building/changing refs. The workflow retains the audit beside the whole-batch contract log. An optional `--observation <JSON>` consumes an actual external GitHub snapshot with timestamp, repository identity, fork main/testing, upstream testing, baseline tag and a published-release API page. It reports observed newer-release count and mirror alignment, explicitly limiting the result to that page. No observation means live upstream/lag remains unverified. The snapshot cannot advance the production baseline or certify security fixes. A testing mismatch requires history/commit/tree/active-ref review; this tool never merges or force-updates it.

Source inventory plus per-file upstream differences supports the periodic semantic review; it cannot decide that upstream replaced a patch. The reviewer compares actual normal/error/cancellation/default/platform behavior and the patch's regression assertions at the selected released commit. Record retained/adjusted/retired decisions with exact source, upstream evidence and rationale. Do this at startup and once before candidate freeze; after freeze do not switch input beneath in-flight gates. Additional scheduled monitoring or an automatic force-sync bot is not implied by this maintenance contract.

## Authorized baseline migration

1. Record current released baseline, actual upstream tag object/peeled commit/tree, live testing heads, active consumer tags/releases and fixed source receipt identities. Check the complete source/module/preset/CLI/API/tests/documentation impact; neither a mutable testing tip nor a GitHub compare merge-base summary is sufficient.
2. Preserve the original main/branch/worktree and necessary source/log/ELF recovery. Use the existing isolated task branch and fixed workspace. Replay/merge only the user-agreed runtime and producer scope, retaining common-before-mobile ordering. Record actual per-path conflicts, resolutions and any upstream replacement decisions; refresh the catalog after collective review, without dropping unexplained features.
3. Update the source-owned baseline/version/tag and self-check defaults together. Keep Go/gomobile/NDK/SDK pins explicit; do not upgrade global tools. Historical manual self-check inputs must supply the matching full `base_commit` and `base_ref`.
4. Complete the entire implementation and related revisions before unified independent review and accurate-source remote gates. Compiler/interface errors join the aggregate repair; no per-item CI exception. Record the actual conflict count (zero only after an actual conflict-free migration), observed newer releases and security-adoption timing from real events, never invent an SLA or infer security acceptance from the count.
5. Reacquire every invalidated receipt listed in the catalog: source/module/replacement, native byte/signature, guest lifecycle/runtime, corresponding source/license, immutable publication and actual consumer identities. Old greens or old byte hashes remain historical. App/mobile owners reacquire their own carrier/ABI/load/network evidence; producer receipts do not replace it.
6. Only after required same-input gates and parent review close, integrate/publish under existing authorization. Preserve immutable active tags/assets until actual consumers migrate; deletion/ref replacement requires the precise authorized cleanup plan. The read-only audit does not grant remote writes, deployment or device-network actions.

## Pending boundaries

Live `testing` synchronization is a separately controlled ref operation when histories diverge; no sync is performed by this code. New tag/index/release/asset IDs and public pins must come from final original bytes. Actual App downloads, safe extraction, library loading, gvisor/mixed behavior and final carriers are App-owned. Android four ABI/Apple device plus simulator slices/final native links, real physical TUN/VpnService/Network Extension, distribution trust and unsupported legacy-OS runtime remain explicit validation boundaries. Refer to `POLARIS_PRODUCTION_RELEASE.md`, `POLARIS_ASSETS.md` and `POLARIS_OPENWRT.md` for the precise producer/platform contract.
