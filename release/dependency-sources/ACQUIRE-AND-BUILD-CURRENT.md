# Acquire the source and build inputs for this distribution

Start with the public `polaris-upstream-native-assets.json` and GitHub release receipt. The exact `sourceCommit`, `sourceTree`, source archive SHA256, per-payload hashes and `distributionMaterials` are authoritative for that run. Do not replace them with a historical desktop candidate commit. The kernel source archive is the exact committed repository; it includes the local sing-tun/MetaCubeX uTLS replacements, patches, generators and workflow recipes, but does not expand Git submodules.

1. Acquire the kernel commit from `https://github.com/polaris-arch/sing-box-polaris` or its named source archive; verify the index SHA256. Use `git submodule update --init --recursive` when using a Git checkout.
2. Use official Go1.27.2. `.github/go-toolchains.json` identifies the official commit/toolchain archives and target-specific patches. `.github/patch_go_for_ios.sh` and the workflows specify their application. Do not treat the retained Go1.25.5 historical materials as the current toolchain. Go runtime license provenance is under `release/licenses/go-1.27.2`.
3. Acquire Go modules at the exact module/version/h1 in the actual index. `go mod download` uses the committed `go.mod`/`go.sum`, including the source-owned replacements. For a replaced external module use its replacement version and h1, not the replaced module's old version. Existing fixed ZIP locations and SHA256 are in `release/polaris-public-source-inputs.json` only for exact matching records; current deltas are in `release/ci/current-module-sources.json`. A Go h1 is a directory checksum and is not the archive's SHA256.
   The source-owned `github.com/libp2p/go-nat` replacement is `third_party/go-nat`: original version `v1.0.1-0.20250821073202-01afc089f138`, commit `01afc089f138bf26b9f467ccba7f53ac34e0c679`. Its `UPSTREAM.json` preserves the exact original ZIP/h1 and per-file identities; `LICENSE` is the full original text. The committed local discovery/mapping completion, caller-owned XML/SOAP HTTP, captured device resolver and identity-checked cleanup changes are part of the kernel source archive, not the original module ZIP. Both the root module and standalone `third_party/sing-quic` module resolve this same local dependency. Do not substitute that ZIP for the patched local source. Controlled SOAP source tests check the actual generated header/XML action and acknowledged mapping key, rather than replacing native reply parsing. The local sing-quic Realm resolver also normalizes mapped IPv4 and filters captured hostname results and control peers to the selected address families; retain these local changes with its source.
4. Cronet154.0.8037.49 uses the fixed wrapper/library module identities in BuildInfo, original driver commit `abcdebebd23da6e74cf9c55ab63024ce66fc0f7b`, and engine `be1be963131154ba82761a7ed85ba426b2027319`. Retained official provenance and build recipes identify the original build inputs. `release/ci/current44-static-cronet-origin-bindings.json` binds static library blobs and direct-link wrappers; shared libraries have their exact byte receipts. These acquisition mappings do not demand a new Chromium build or assert bit-for-bit reproduction.
5. Follow the same-source `.github/workflows/build.yml` jobs for the selected target's build environment, build tags and archive steps. No signing keys are included.
6. WinDivert fixed upstream source, original driver-byte checks and build instructions are in `windivert/`. The in-tree wrapper selects the upstream LGPLv3 option.

Notices retained in the source archive and inline final index are shared distribution materials. The release receipt associates every selected payload with them; where a package already carries a notice, the evidence records its exact internal path and hash. Current notice selection preserves the original texts, with source paths and byte-offset hashes. Attribution is not a grant of trademark or association permission. Remaining explicit review items in `release/ci/distribution-materials.json` must be resolved before publication, separately from the user's inventory acceptance. This document is an engineering acquisition/build guide, not a legal opinion.
